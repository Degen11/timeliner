# Quick Reference

Codebase cheat sheet for Timeliner. Reference this instead of reading source files.

---

## Entry Points

| File | What it does |
|------|-------------|
| `src/main.jsx` | React root: StrictMode → BrowserRouter → App |
| `src/App.jsx` | ErrorBoundary → MotionConfig → hydration → routes |
| `src/components/timeline/TimelinePage.jsx` | Main page: orchestrates all views, modals, filtering, pagination |
| `src/components/shared/SharedViewPage.jsx` | Read-only view for shared timelines (`/s?id=...`) |
| `src/store/useTimelineStore.js` | Zustand store root: composes slices, persistence, sync |
| `api/parse.js` | Serverless: Claude AI event extraction |
| `api/share.js` | Serverless: share link CRUD via Supabase |

## File Patterns & Conventions

### Naming
- Components: `PascalCase.jsx` (e.g., `EventCard.jsx`, `AddEventModal.jsx`)
- Utilities: `camelCase.js` (e.g., `dateUtils.js`, `exportHelpers.js`)
- Store slices: `camelCaseSlice.js` (e.g., `eventsSlice.js`)
- All frontend files are `.js` or `.jsx` (no TypeScript)

### Component Pattern
- All view components and cards use `memo()` wrapper
- Props destructured in function signature
- Store access via individual selectors: `useTimelineStore((s) => s.field)`
- No barrel exports — direct imports everywhere

### Store Slice Pattern
```js
export function createFooSlice(set, get, { persist, sync }) {
  return {
    fooState: initialValue,
    fooAction: () => {
      set({ fooState: newValue })
      persist({ ...get(), fooState: newValue })
    },
  }
}
```
Slices receive `persist` (debounced local save) and `sync` (debounced remote sync) as injected helpers.

### Import Alias
`@/` maps to `src/` (configured in `vite.config.js`):
```js
import EventCard from '@/components/timeline/EventCard'
import { VIEWS } from '@/utils/constants'
```

## Common Tasks

### Add a new view mode
1. Create component in `src/components/timeline/` (wrap with `memo()`)
2. Add enum to `VIEWS` in `constants.js`
3. Add render branch in `TimelinePage.jsx` (and `SharedViewPage.jsx` for shared views)
4. Add button to view switcher in `TimelineToolbar.jsx`

### Add a new event field
1. Add to event object in `eventsSlice.js` actions
2. Add to `mapEventToRow()` / `mapRowToEvent()` in `db.js`
3. Add column to `supabase-migration.sql`
4. Add to `normalizeCSVEvent()` / `normalizeJSONEvents()` in `importHelpers.js`
5. Add UI in `AddEventModal.jsx` and `EditEventModal.jsx`
6. Display in `EventCard.jsx` and relevant view components

### Add a new export format
1. Add function to `exportHelpers.js`
2. Add button/option in `ExportModal.jsx`

### Add a new tag
1. Built-in: add to `TAG_OPTIONS` and `TAG_MAP` in `constants.js`
2. Custom: users create at runtime via `addCustomTag()` store action

## Gotchas

1. **Date timezone bug:** ISO dates at UTC midnight roll back in negative-UTC timezones. `dateUtils.js` adds 12 hours before formatting to prevent this. Don't use `new Date(isoString)` directly for display.

2. **Photo storage:** Photos are Blobs in IndexedDB, not base64 strings. Legacy base64 entries are auto-migrated. Object URLs are cached and must be revoked on deletion.

3. **Store slice ordering:** Slices are spread in order: events → photos → ui → timelines. The `restored` object from localStorage is spread last, overwriting defaults. If you add new persisted fields, add them to the `fields` array in `useTimelineStore.js`.

4. **Rate limiter resets on cold start:** The in-memory rate limiter in `api/rateLimit.js` doesn't persist across Vercel serverless instances. It still protects against bursts within a warm instance.

5. **Supabase RLS requires device_id:** Every Supabase query must include the `x-device-id` header (set automatically by `supabase.js`). Without it, RLS policies return empty results.

6. **Component location:** Many shared components (TextInput, SearchInput, MultiSelect, etc.) live in `src/components/shared/` despite legacy directories existing at `input/`, `filters/`, `review/`. The `shared/` versions are canonical.

7. **No TypeScript:** The entire project is JavaScript. Type safety comes from consistent object shapes and the ESLint react-hooks plugin catching stale closures.

8. **Lazy-loaded views:** MapView and GraphView use `React.lazy()`. They must be wrapped in `<Suspense>` wherever rendered. If you add a new heavy view, follow this same pattern.

9. **commitEvents is the only safe way to mutate events.** Never `set({ events })` directly in a slice — it bypasses undo history and persistence.

10. **syncEvents deletes orphans.** After upserting local events to Supabase, it queries all remote events and deletes any not in the local array. This is intentional (handles deletion sync) but means the local array is the source of truth.
