# Device ID, the sole sync credential, is embedded in signed photo URLs shown to users

Confirmed by detect-security: storagePath is deviceId/filename (photoSync.js:20-21), createSignedUrl on it (photoSync.js:126) returns a URL containing that path, rendered via useResolvedPhotos (used by EventCard, EventDetailView, PhotoPreview, EditEventModal) when a photo is not local; supabase.js:30 and migration RLS (timelines/events/storage) authorize solely on x-device-id, so the leaked id grants full read/write/delete. No trap or documented acceptance found.

Evidence:
- src/lib/photoSync.js:20
- src/lib/photoSync.js:126
- src/hooks/useResolvedPhotos.js:26
- src/lib/supabase.js:30
- supabase-migration.sql:52
