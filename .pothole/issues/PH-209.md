# Import web worker is a stale copy of importHelpers that missed the date-validation and ICS fixes

Confirmed by detect-code: All four routes fail. evidence: importWorker.js:25-33 validates with new Date(str), which in node/V8 accepts 2024-02-30 and 2023-02-29 (rolls to March), while dateUtils.js:55 uses safeParse. Worker parseICS (:150) has no line unfolding, all-day DTEND shift or RRULE, and parseMarkdown (:222) strips only the first date token, all fixed only in importHelpers.js (108/136/238) by 3f3f102. The worker's only commit is e6985f8. useFileImport.jsx:83 routes JSON/ICS/Markdown files over 50KB to the worker, so the drift is reachable. Not a trap: it is one parser per format copied from a shared origin, not separate contexts. No comment documents the divergence.

Kind: duplication.

How to fix: Delete the hand-copied parsers in importWorker.js and import normalizeJSONEvents, normalizeICSEvents and normalizeMarkdownEvents from importHelpers (the worker is already created with type module).
